# Plan de clases: Vibe coding con OpenCode y portafolio profesional

**Duración:** 3 clases de 2 horas (6 horas en total)  
**Perfil del alumno:** desarrollador con nociones de React y Next.js, y experiencia desplegando en Vercel.  
**Proyecto:** portafolio profesional construido a partir de la experiencia y los proyectos del CV.

## Objetivo general

Construir y publicar una primera versión de un portafolio profesional mientras el alumno aprende a colaborar con OpenCode: proporcionar contexto, dividir el trabajo en tareas pequeñas, revisar los cambios, iterar y documentar el proyecto. Como parte del proceso, desarrollará y probará un Skill reutilizable para una tarea concreta del portafolio.

## Resultados esperados

Al finalizar las tres clases, el alumno tendrá:

- Una primera versión funcional y publicada —o lista para publicar— de su portafolio.
- Contenido profesional seleccionado y verificado a partir de su CV.
- Un `README.md` que explique cómo ejecutar, actualizar y desplegar el proyecto.
- Un Skill propio, probado con ejemplos y documentado.
- Un flujo de trabajo básico para pedir, revisar y mejorar cambios asistidos por OpenCode.

## Preparación previa

El alumno debe traer, si están disponibles:

- Su CV actualizado. Puede preparar una copia sin datos personales que no quiera usar en el sitio.
- Enlaces a proyectos, repositorios, demos, artículos u otros trabajos que quiera destacar.
- Una lista de roles o tipos de oportunidades profesionales que busca.
- Acceso al repositorio y a la cuenta de Vercel que se utilizarán.

El alumno valida todo el contenido antes de publicarlo. OpenCode puede ayudar a organizar o redactar la información, pero no debe inventar experiencia, métricas ni resultados.

## Clase 1 — Del CV a la propuesta de valor

**Objetivo:** convertir la experiencia profesional del alumno en contenido verificable y una especificación breve para el portafolio.

### Agenda (120 minutos)

| Minutos | Actividad |
|---|---|
| 0–10 | Acordar el objetivo del sitio, su público y el tipo de rol que quiere comunicar el alumno. |
| 10–25 | Introducción al flujo con OpenCode: aportar contexto, pedir una tarea acotada, revisar los cambios e iterar. |
| 25–45 | Analizar el CV: identificar experiencia, logros, tecnologías y proyectos; anotar qué datos necesitan confirmación. |
| 45–60 | Redactar la propuesta de valor y definir el tono del portafolio. |
| 60–70 | Pausa breve y revisión de hallazgos. |
| 70–90 | Definir las secciones y el recorrido del sitio: presentación, experiencia, proyectos, habilidades y contacto. |
| 90–105 | Escribir una especificación para OpenCode con objetivos, contenido, restricciones y criterios de aceptación. |
| 105–115 | Ejercicio individual: pedir una propuesta de estructura a OpenCode y contrastarla con la especificación. |
| 115–120 | Cierre y preparación de materiales para la siguiente clase. |

### Explicación breve

OpenCode puede producir mejores resultados cuando conoce el propósito del sitio, su público, el contenido confirmado y cómo se evaluará una tarea. Una solicitud clara reduce ambigüedades. La IA puede ayudar a organizar y redactar, pero el alumno debe validar cada dato profesional.

### Ejercicios prácticos

1. **Extracción del CV:** crear una lista de experiencias, logros y proyectos, anotando para cada uno qué evidencia o enlace lo respalda.
2. **Propuesta de valor:** redactar una presentación profesional breve, orientada al público definido.
3. **Ficha de proyecto:** describir un proyecto con problema, rol, decisiones técnicas, resultado y enlaces.
4. **Prompt con criterios:** pedir a OpenCode una estructura inicial del sitio. Revisar si responde al objetivo y solicitar cambios concretos cuando haga falta.

### Entregable de la clase

- Contenido priorizado para el portafolio.
- Una propuesta de valor breve.
- Una especificación inicial del sitio.
- Lista de información que falta verificar o complementar.

### Documentación

Iniciar el `README.md` con el propósito del proyecto, el público objetivo y el alcance de la primera versión. Mantenerlo breve y útil para retomar el trabajo.

## Clase 2 — Construcción iterativa y primer Skill

**Objetivo:** construir una primera versión funcional y crear un Skill para una tarea repetible del portafolio.

### Agenda (120 minutos)

| Minutos | Actividad |
|---|---|
| 0–10 | Revisar la especificación y acordar las prioridades de la sesión. |
| 10–25 | Inspeccionar el proyecto con OpenCode y confirmar cómo ejecutar la aplicación antes de modificarla. |
| 25–45 | Implementar la estructura principal y la navegación mediante tareas pequeñas. |
| 45–65 | Construir la presentación y la experiencia profesional con contenido validado. |
| 65–75 | Pausa breve. |
| 75–90 | Construir la sección de proyectos con fichas consistentes y enlaces relevantes. |
| 90–100 | Revisar el diseño en móvil y resolver un problema priorizado. |
| 100–112 | Crear un Skill para una tarea recurrente y probarlo con una ficha de proyecto. |
| 112–120 | Revisar los cambios, registrar decisiones y definir pendientes para la última clase. |

### Explicación breve

El *vibe coding* se trabaja como un ciclo: dar contexto, pedir un cambio pequeño, revisar el resultado y decidir qué ajustar. No se trata de aceptar automáticamente todo lo que genera la IA. Un Skill permite guardar instrucciones para realizar una tarea específica de forma más consistente.

### Ejercicios prácticos

1. **Implementación por etapas:** pedir a OpenCode una sección o funcionalidad por vez, evitando una solicitud demasiado amplia.
2. **Revisión del cambio:** inspeccionar qué archivos cambiaron y comprobar que el resultado cumple la tarea solicitada.
3. **Fichas consistentes:** redactar dos fichas de proyecto con la misma estructura y tono.
4. **Crear un Skill:** redactar instrucciones para revisar fichas de proyectos. El Skill debe indicar:
   - Qué tarea resuelve y cuándo utilizarlo.
   - Qué información necesita recibir.
   - Qué criterios debe comprobar.
   - Qué hacer cuando falten datos.
   - En qué formato presentar sus observaciones.
5. **Probar e iterar:** ejecutar el Skill con una ficha completa y otra incompleta. Ajustar sus instrucciones para que señale vacíos y no invente información.

### Cómo adquirir y desarrollar Skills

- **Adquirir:** consultar la documentación y los ejemplos disponibles de OpenCode; entender qué problema resuelve cada Skill y revisar sus instrucciones antes de utilizarlo.
- **Desarrollar:** seleccionar una tarea repetitiva, escribir instrucciones específicas, probarlas con casos reales y refinarlas según los resultados.
- **Criterio de calidad:** el Skill resuelve una tarea concreta de forma repetible, hace explícitos sus límites y no completa con datos inventados la información que falta.

La ubicación y el formato de los Skills se confirmarán según la versión de OpenCode y la estructura del proyecto utilizada durante la clase.

### Entregable de la clase

- Primera versión funcional del portafolio.
- Un Skill inicial para revisar fichas de proyectos.
- Lista priorizada de ajustes pendientes.

### Documentación

Ampliar el `README.md` con requisitos, instrucciones para instalar dependencias y ejecutar el proyecto, una descripción de sus secciones y una nota sobre cómo probar el Skill.

## Clase 3 — Calidad, documentación y publicación

**Objetivo:** revisar y pulir el sitio, completar la documentación y dejarlo publicado o listo para desplegar en Vercel.

### Agenda (120 minutos)

| Minutos | Actividad |
|---|---|
| 0–10 | Revisar el estado del proyecto y seleccionar los problemas de mayor impacto. |
| 10–30 | Revisar contenido, enlaces y consistencia visual; confirmar la exactitud de la información profesional. |
| 30–50 | Comprobar experiencia móvil, accesibilidad básica y metadatos; priorizar correcciones. |
| 50–60 | Pausa breve. |
| 60–75 | Pedir a OpenCode una revisión de alcance definido y evaluar sus recomendaciones. |
| 75–90 | Probar el Skill con distintos ejemplos y documentar su uso y límites. |
| 90–105 | Completar el `README.md` y hacer una revisión final del repositorio. |
| 105–115 | Desplegar en Vercel o ensayar el flujo de publicación; validar la URL. |
| 115–120 | Demostración final, aprendizajes y próximos pasos. |

### Explicación breve

Una revisión generada por IA es una fuente de sugerencias, no una lista que haya que aceptar automáticamente. El alumno debe verificar las observaciones, priorizar cambios por impacto y volver a comprobar el sitio después de aplicarlos. La documentación final debe ayudar a otra persona —o al propio alumno más adelante— a ejecutar y actualizar el proyecto.

### Ejercicios prácticos

1. **Revisión guiada:** solicitar a OpenCode que busque problemas concretos, como enlaces rotos o inconsistencias entre fichas, y validar manualmente cada observación.
2. **Priorización:** clasificar las sugerencias como necesarias para publicar, importantes para mejorar o aplazables.
3. **Prueba del Skill:** aplicarlo a una ficha con información completa y otra incompleta; confirmar que detecta vacíos sin inventar respuestas.
4. **Documentación:** completar el `README.md` para que incluya:
   - Propósito del sitio.
   - Requisitos e instrucciones de ejecución.
   - Secciones principales del proyecto.
   - Cómo actualizar el contenido.
   - Cómo usar y mantener el Skill.
   - Cómo desplegar el proyecto.
5. **Publicación:** desplegar en Vercel y comprobar la URL, los enlaces y la visualización móvil.

### Entregable de la clase

- Portafolio publicado o listo para publicación.
- `README.md` con instrucciones para ejecutar y mantener el proyecto.
- Skill probado y documentado.
- Lista breve y priorizada de mejoras futuras.

---

## Criterios de éxito

Al terminar el recorrido, el alumno puede:

- Proporcionar contexto y criterios de aceptación claros a OpenCode.
- Dividir el trabajo en cambios pequeños y revisar qué se modificó.
- Convertir información del CV en contenido profesional verificable.
- Crear, probar y mejorar un Skill para una tarea real.
- Documentar cómo ejecutar, actualizar y publicar el proyecto.
- Explicar las decisiones tomadas y qué aspectos del resultado validó personalmente.

## Resultado final del proyecto

Un portafolio profesional inicial, con contenido validado, publicado o listo para Vercel, documentación breve y un Skill reutilizable para apoyar el mantenimiento de sus fichas de proyectos.
